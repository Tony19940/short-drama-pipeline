# 直接粘给云端 agent 的一段话

> 用法：把下面分隔线之间的内容整段粘贴，并附上五个文件
> （`CLOUD-REBUILD-TASKS.md`、`CLOUD-PIPELINE.md`、`DIAGNOSIS-ep01.md`、`validate_shots.py`、`gold/` 两个 json）。

---

本地已经审完你发来的三份材料，结论和改造方案在附件里。先说三件最要紧的事，然后按任务单做。

**第一，你自我诊断的第 1 条方向反了，不要按它改。**

你写「末帧续不够严格，很多镜头仍用独立生成」，隐含结论是要更严格地执行末帧续。照这个方向改会让画面更坏。

真正的问题是镜头图把 `cut: continue` 标在了不该标的地方。全集 10 镜有 9 镜标 continue，串成从 SH001 一路到 SH010 的直线，其中至少三处不具备续接条件：SH004（索菲娅首次出现）的父镜是校服单据空镜、SH007（皮萨）的父镜是索菲娅独自缝纫、SH009（罗丝在走廊）的父镜是索菲娅在车间 —— 都没有共同人物，SH009 还换了空间。

于是两条路都是死的。严格执行末帧续，模型拿到一张不含目标角色的画面，只能凭空造脸，这就是你看到的角色漂移。不执行、改回独立生成，就回到每镜重新想象，这就是拼接感。**要修的是图，不是执行力度。**

判据是人物交集：同场且与父镜有共同人物才吃末帧；覆盖切到另一个人时用本镜锁定的设计首帧，`cut` 仍写 continue（地理和光位连续），但首帧不能用末帧。跨场一律硬切，首帧从新场 blocking 改。

**第二，有三个问题你没自查到，而它们直接造成"不像导演拍的"。**

其一，六成镜头在慢推，零拉镜。你的 `move` 是自由文本（`"static + gentle slow push-in"`、`"pan/push"`），所以任何配比检查都失效。把它按语义归一到枚举后是 `push×6 static×2 pan×1 track×1 pull×0`。你禁了 orbit 和 crash zoom 是对的，但把 push 写进了几乎每一镜 —— 环绕之后第二明显的 AI 味就是镜头永远在缓慢前进。全集没有一次拉开呼吸。

其二，`look` 全是情绪形容词（`oppressive busy atmosphere`、`dignity strength`、`restrained shock fate`），十镜没有一个字描述光。这一格应该是物理连续性：光位、景深、站位，要能对着 blocking 检查。光位不锁死，相邻镜必然变色温 —— 观众说不出哪里怪，只觉得假。光位要锁在场上，`sets.json` 每场一个 `light` 字段，本场每镜的 `look` 复述它。

其三，你从来没做过镜内调度。10 刀 49 秒，没有一镜超过 6 秒，所以拆段机制实际从未启用。在 AI 制作里这点被严重低估：**每一刀都是一次让模型重新想象场景的机会**，切得越碎漂移越多。导演的做法相反 —— 更少、更长的镜头，把变化放进画框内部靠走位完成。另外 SH006 和 SH009 标了 split 但都正好 6 秒，不需要拆；6 秒拆两段只是白多一个接点。

**第三，单集规格已锁定：60–75 秒 / 8–10 镜，80 集一致。**

之前三个来源不一致（剧本 90–120 秒、本地 50–75 秒、你实际 49 秒），现已定案。你的 49 秒低于下限，会被判 ERROR。

**怎么做**

附件里的 `validate_shots.py` 是单文件零依赖校验器，直接放进你的流程。现状对比：

```
你的 ep01：  10 镜 49s   ERROR 226 / WARN 1
金标准：      8 镜 64s   ERROR 0   / WARN 0
```

金标准（`gold/Episode1_shots.gold.json`）能过，说明这套规则可满足，不是刁难。它是同一集的导演级设计：两场两条轴、光位锁在场上、`static×4 push×3 pull×1`、含一个 12 秒 master 拆成同轴续段。**逐字读一遍，它就是目标形态。**

按 `CLOUD-REBUILD-TASKS.md` 从 T0 做到 T10。顺序有依赖，不要跳着做 —— T1（建 sets 注册表）不做完，T5 以后全是白工，因为没有场就没有轴线、没有 blocking、首帧无处派生。每项都有验收命令，每完成一项跑：

```bash
python3 validate_shots.py --sets sets.json --shots ep01_shots.json --warn-as-error
```

退出码 0 才算完成。**零 ERROR 才准进出图阶段，不要"先过再改"。**

有两个关键设计要理解，不然会做错：

一是 `shots.json` 必须是唯一真源，`video_prompt` 必须在 JSON 里，markdown 视图由它生成而不是反过来。你现在结构在 JSON、提示词在另一份 MD，这等于没有校验 —— 运镜措辞与声明不一致、orbit 泄漏、台词泄漏这三类问题在分家架构下原理上查不出来。

二是超过 6 秒的镜头要拆同轴续段，但**拆的是生成单元，不是剪辑点**。`lens`/`axis`/`setup`/`move`/`look` 一字不改，段间末帧续，拼接不加转场 —— 成片上那是一个长镜。这叫隐形接点，和拼接感正好相反：拼接感来自机位跳变，不来自帧的连续。

最后，音频那条你自查对了，但方案要补一层：**换成同长静音轨，不是删音轨**。删掉会让审片轨报错（它要把 `[0:a]` 压低当背景床），统一的流布局也让 `concat -c copy` 不会崩。命令在 T8 里。顺带把末帧提取从 `-sseof -0.1` 改成 `-0.05`，离真正末帧更近，续接精度更高。

做完 ep01 交本地抽检，抽检项：相邻镜有没有变色温、三个近景对 face.jpg 看脸有没有漂、换场是不是硬切、有没有"一直在慢推"的观感、环境底噪在切镜头处有没有断。
