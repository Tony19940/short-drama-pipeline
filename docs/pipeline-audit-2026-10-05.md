# 短剧流水线审计与改进方案

日期：2026-10-05（Asia/Phnom_Penh）<br>
对象：当前仓库，以及《一瑞尔》EP01 `ep01-rhythm-v2` 的实际生产路径<br>
范围：只读代码与生产证据审计；不改剧本、分镜、资产、审批、模型配置，不运行测试，不提交付费生成。本文是改进方案，不代表整改完成。

## 一、结论

主要缺陷是各阶段之间没有统一且强制的交接契约。仓库已有场卡、状态检查、预演、视觉证据、指纹与人工审批，但不同入口执行的规则不一致；项目专用脚本能够离开这些保护直接生成和剪辑。

《一瑞尔》的例子同时暴露了导演设计、生成执行和剪辑验收问题。SH015 原片有铜钱闪光，当前剪辑却选取闪光前的片段。这个事实能够证明流程会丢掉模型已生成的核心事件，不能用来证明视频模型做不到该事件。

应把目标设为：稳定交接、错误能被发现、证据可追溯、返工范围可控。流水线不能保证所有创作或所有随机生成都完美；它应当保证不合格候选不会被无依据地当成合格成片。

## 二、证据边界

- 已证实：新版 53 镜与默认 28 镜合同并存；默认检查报告认证的是旧 28 镜。
- 已证实：专用生成/剪辑入口没有使用正式导演台的完整关卡链。
- 已证实：局部剪辑丢掉铜钱闪光；付款动作重复，首次揭示与清点之间存在理解跨度。
- 已证实：技术检查与 ASR 报告明确写了不是整集审批，未把新版 keyframes 强写为 pass。问题包含候选交付前没有完成段落理解验收，不能描述为所有关卡都被伪造通过。
- 代码风险：缺失交接 JSON 时部分 assert 直接返回、默认填入静音测试 pass、critic 必须挑一版而无全部拒绝出口。尚未逐一运行失败用例，不能声称每个潜在分支都在这集实际触发。
- 本次不评价未来文本模型或其他视频模型的产品能力；是否提升，要在同一任务、同一契约、同一审阅标准下比较。

## 三、缺陷与整改

### 1. 生产版本没有贯穿整条流程（P0）

**证据**：新版 `.pipeline/shot_list.ep01-rhythm-v2.json` 为 53 镜 / 111 秒；默认 `shot_list.json` 为 28 镜 / 159 秒。`legacy_check_report.ep01-rhythm-v2.json:5–8` 明示 `check_prod` 只检查旧版。`scripts/director/shot_repo.py:36–44` 走 context 的 artifact_name；项目专用脚本则直接写死新版路径。

**影响**：分镜、帧、生成包、审片与审批可能各自正确，却检查不同版本；换文本模型不能修复这个错位。

**整改**：建立单一 revision manifest，绑定 production / episode / revision、所选剧本和分镜哈希、规则版本、资产、帧、请求、take、剪辑清单与音轨。所有入口解析同一个上下文；旧格式仅作为显式导入。命令和报告必须展示正在检查哪版、多少镜，禁止静默退回旧表。

**验收**：指定新版后，检查、预演、生成和剪辑都读 53 镜；旧 28 镜仍能作为独立归档读取。任何上游变动使对应下游证据过期，而不是用旧 pass 继续。

### 2. 审批和完成标记存在缺省放行（P0）

**证据**：`scripts/director/shot_table.py:1263–1264` 自动补 `design_steps_done=[1..7]` 和 `visible_change_without_dialogue='pass'`；`858–859` 只检验字符串。`scripts/director/pipeline.py:1424–1447` 对缺失 packages/keyframes/clips JSON 直接返回。

**影响**：缺资料、没审阅和已经通过的边界不清楚；格式清洗承担了审批语义。

**整改**：清洗只规范数据，不能制造完成或合格证据。新生产任务缺 required artifact、缺 reviewer 或哈希不匹配必须 unknown/block；允许 legacy 路径时必须显式声明，并禁止它认证新版。草稿预览仍可生成，但要独立标识，不能进入正式发布状态。

**验收**：空资料不能进入正式投产/发布；仅补一句 pass 不能认证静音理解；报告能定位缺少的证据，保留正常草稿查看能力。

### 3. 分镜合同偏重镜头术语，叙事信息没有成为可追踪对象（P0）

**证据**：已有 `shot_job / new_info / in_from / out_to / evidence` 和场卡揭示顺序，但不等于画面实现。`shot_table.py:696–708` 无逐镜 state 只 warning；`CHAR_STATE_KEYS` 在第 52 行主要追踪服装、绑法和持物。新版缺结构化 state。金额、持有者、显隐、支付完成与观众知识变化没有得到完整跨镜跟踪。

**整改**：先建立段落合同：观众起初知道什么、必须看到哪些证据、先后关系、何时允许揭示、段落结束能得出什么结论。每个关键证据映射到具体镜头或连续动作，不要求每个证据都多开一镜。补关键道具状态：owner / location / quantity或amount / visible / action_phase，以及必要的观众与角色知识状态。

例：瑞尔归阿姨；美元另行出现；支付完成才触发；头盔此前为空；男主看到与验证之后才提出返现假设。此处不能只写“新信息：返现”。

**验收**：付款未完成不能提前触发；上一镜实际已放钱，下一镜不能无解释重新从手持钱开始；返现与货币转换不会在合同中混为一谈。状态检查只能证明一致性，实际观众理解仍要看片。

### 4. 评审倾向于选出最好的一版，缺少“不合格全退回”（P0）

**证据**：`scripts/director/design_critic.py:160–201` 检查分数 0–10、notes、pick 与 why 的格式，不设内容合格出口；`143–157` 的确定性兜底按景别、视点、覆盖类型、warning 排序。

**整改**：区分候选排名与投产资格。保留多方案比较，允许 reject_all / needs_rework；核心因果缺失、剧情改写、关键动作无法展示为拒绝条件。critique 不可用时只给“暂定推荐”，不能替代内容审阅。

**验收**：三版都不能讲清规则时，流程退回场设计；不会因为必须 pick 一个编号而投产。由审阅者指出具体缺失证据和受影响的段落。

### 5. 设计尾帧、实际末帧和剪辑出点混用（P0）

**证据**：`AGENTS.md` 把设计尾帧落为 `SHxxx-last.jpg`；`PIPELINE.md` 视频规则则把 `-last.jpg` 解释为视频抽出的实际末帧，并要求设计尾帧走 end_frame。不同文档对同一名称赋予不同含义。

**整改**：明确 planned_start / planned_end、actual_start / actual_end、edit_in / edit_out；元数据必须写类型、来源媒体哈希和取帧时间。旧文件可以保留，通过适配器解释，不能仅按后缀猜语义。图像父图用于身份/场景继承，与故事时间状态继承分开记录。

**验收**：设计落点不能冒充生成已经到达；实际视频末帧不能代替人审的设计目标。同机位续拍和换机位覆盖使用不同规则，实际剪出状态能与下一镜剪入状态对照。

### 6. 预演与场级试样不是完整的必经关卡（P0）

**证据**：`scripts/director/show_policy.py:76–77` 预演要求默认 False；scene_rehearsal_required 在 `162–164` 主要提升 animatic_required，并不是视频场级试样验收。`scripts/director/animatic.py:414–425` 审批记录绑定输入 fingerprint，但没有要求实际预演片存在、绑定工作音轨和看片结论。

**整改**：分两次验证。付费批量前用首尾状态/必要事件卡和中文工作音轨做段落预演；再对最难的核心因果段落生成最小连续视频试样。语音/动作模型烟测与叙事试样分开，四角色声线试样不能认证“返现段落看得懂”。只把已通过段落扩到全场/全集。

**验收**：没有实际可看的预演、缺核心事件卡或工作声轨，不得登记完整审剧情通过。段落试样需能回答明确问题，并绑定被看的 MP4、音轨和输入哈希。

### 7. 模型适配不只需要参数与 Prompt，还需要风险分工（P1）

**证据**：已经有 model profile、首帧/首尾帧路线和请求哈希；生成请求详细写了金额、张数与动作，但原画面仍有面额、张数、动作边界偏差。

**整改**：区分创作设计与模型执行。导演先定可理解的覆盖；生成包编译成模型可执行动作，并检测重复/冲突要求。普通表演给生成模型，精确金额、可读文字、可计数道具与触发特效可由受控资产/后期承担。高风险镜头增加动作阶段与关键事件目标，不能依赖模型任意时刻完成后再硬剪。

**验收**：同一契约下模型能力失败可以归因到具体动作；必要时选择补镜、合成或改变拍法，有限次数失败后退回设计。不能把剪辑漏事件记成模型生成失败。

### 8. 剪辑按秒数和声音裁片，缺少关键事件保护（P0）

**证据**：`productions/011-one-riel/.pipeline/assemble_seedance_v2_preview.py:31–62` 按计划时长/声音活动决定窗口、速度并 tpad 克隆尾帧。`fix_cut_stutter_v2.py:7` 写死 SH015 的 0.1–0.6 秒窗口；原片约 1.3 秒发光，因而被丢弃。两份脚本记录 source_hash，但不记录事件区间。

**整改**：建立证据驱动的剪辑清单 EDL：source_take、媒体哈希、in/out、dialogue_span、必须保留事件及可读持续区间、动作阶段、speed、hold 理由。缺关键事件不能靠缩时长、静帧或快放自动填过。时间不足先反馈导演，不能为了原计划总秒数破坏因果。

**验收**：铜钱发光区间不在 EDL 内必报错；关键事件不能在缩速后短到看不清。旁白/对白留全不能被当作动作齐全。重剪使整段审阅证据过期，需要复看片。

### 9. 质量验证缺少段落理解层（P0）

**证据**：`scripts/director/qc_layers.py` 已正确区分 technical/text/visual/performance，且 visual 必须绑定媒体哈希；但第 67 行 performance 固定 unknown，第 87–90 行 helper 只看 visual 是否 pass。项目 `review_seedance_v2.py:24–26,49–55` 技术/ASR 检查明确不等于整集审批。技术连续和没有整句缺失仍未发现返现触发被剪掉。

**整改**：统一验收为技术、身份/画面、表演/台词、动作/连戏、段落理解、发布完整性。适用项不得 fail/unknown 后被合并成总 pass；草稿/partial 作为明确交付类别，正式发布另设门。场级验证看实际视频，静音测试只验证可视因果，带声盲看验证完整故事；二者不能用文字评分替代。

**验收**：审阅者只看看片材料、不读解释，就能回答该段落预设问题；返现段至少说清花了什么、钱在哪里出现、为何是额外返现。审阅不能靠“告诉他正确答案后觉得能懂”通过。审片结论绑定素材与 EDL 哈希。

### 10. 固定艺术规则与模型反馈需要分层（P1）

**证据**：文档混有旧无声 Hailuo/H3 流程与新 Seedance 原声流程；镜数/分钟、对白后反应镜、静态机位比例、邻镜变化数等是通用风格规则。项目 53 镜 /111 秒约 28.6 镜/分钟，并不意味着电影表达自动变好。

**整改**：统一权威规则版本。硬门只挡缺证据、矛盾和流程错误；镜数、景别分布、反应时长、运镜比例是带理由的创作提示。保留导演自由，拒绝为评分凑景别或切镜。错误按 story / design / frame / video / edit / review / infra 分流；每次记录原因、证据和最早失效阶段，模型经验库只收可归因的模型执行问题。

**验收**：允许为同一因果动作保留连续镜头，允许有意义的静止；不能因少于目标镜数或没有强行运镜而否决已清楚表达的场景。反馈能区分发光没生成与发光被剪掉。

## 四、建议的生产主线

1. 剧本锁定：明确人物目标、冲突、翻转和世界规则。
2. 段落合同：定义观众知识变化、关键证据及揭示顺序。
3. 场设计与候选：舞台/视点/覆盖、动作状态；独立评审允许全部退回。
4. 关键帧与带声预演：验证段落表达和节奏，不凭文字表直接批量付费。
5. 模型编译与最小段落试样：确认核心拍法可执行；不合格先局部返工。
6. 单镜视频验收：记录实际事件区间、起落状态、对白与take。
7. EDL 剪辑：保护事件/台词；可读时间优先于原计划秒数。
8. 段落与整集审阅：实际影片验证因果、连戏、表演、声音、节奏。
9. 发布：完整性与版本证据检查；partial 永远不自动升级为正式成片。

## 五、落实顺序

### 第一批：堵住跨阶段丢失信息（P0）

1. 统一 revision manifest / source resolver / 权威规则；消除首尾帧语义冲突。
2. 去掉默认 pass 与缺交接文件放行；将技术、创作、段落和发布状态分开。
3. 补段落证据合同、道具状态和实际事件标注；接通 EDL 关键事件保护。

这三步要贯穿所有入口，包括临时脚本和批量生成入口，不能只新增一份说明文档。

### 第二批：把评审变为真实生产关卡（P0）

4. critic 增加全退回；将文字候选评审与实际看片分开。
5. 预演绑定真实影片与工作音轨；核心连续段落试样合格后再扩量。
6. 实际剪辑后增加段落盲看，任何新剪辑或换take都使相关审批过期。

### 第三批：提高效率与艺术选择（P1）

7. 模型适配/风险分工与错误归因闭环，保留幂等请求、下载恢复、试样复用。
8. 把固定电影规则改为可解释提示，用已有失败案例做回归样本。

## 六、什么叫“流水线足够可靠，可以更换拆镜模型”

不以总评分或漂亮 Prompt 定义，而以一组失败样本是否被正确拦截定义：

- 读错版本、重复/缺镜、缺证据、旧审批复用被阻断。
- 首帧已完成动作、下一镜重复付款、美元提前出现能被定位。
- 原片闪光却被剪掉、台词没缺但动作缺失、静帧凑时长能被报告。
- 可接受片段和候选片段、partial 与 release 有清楚状态。
- 每个失败都能返回最早失效环节，避免整集重生成。

这些是后续实施与回归验证的验收样本，本轮未运行测试、未宣称已经全部实现。

换拆镜模型时保持同一版剧本、段落合同、执行模型和预算，比较因果证据覆盖、跨镜状态错误、可生成性、修改成本与盲看理解；分别评估结构设计和画面美学。更强文本模型可以改善视点、调度、表演与镜头选择，但不能代替真实看片或保证视频模型逐项执行。

## 七、应保留的现有能力

- 角色/场景主图复用、父图编辑、版本保留。
- 分镜与视频能力档、首帧/首尾帧适配。
- 草稿、人审锁定、指纹与 stale 的设计方向。
- hash-bound 视觉证据，技术验证不等于视觉通过。
- 实际请求/媒体哈希、任务幂等、断点下载、已合格试样复用。
- 音轨分工、中文原声工作轨、明确 partial / not episode approval。

应接通与补强现有能力，不需要推倒整个仓库再写一套平行流水线。
