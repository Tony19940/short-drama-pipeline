# 给 Codex / Cursor 的改造总令

你正在改造一个**已经存在**的短剧生产流水线，不是从零新建一条。

规则来源只有这些文件，不要另开框架：

1. `短剧流水线_Agent岗位说明书.md`（完整规则）
2. `短剧流水线_Agent落地包/交接字段表.md`（输入输出字段）
3. `短剧流水线_Agent落地包/prompts/`（各岗系统提示词）

## 必须遵守

- 先扫描现有仓库，列出「现有模块 / 文件 → 下列 11 岗」对照表，等确认后再改代码。
- 映射到这 11 岗，不要新增我们没锁过的环节。
- 不要把 5.1 和 5.2 合成一步。
- 不要把视觉资产当成关键帧。
- 不要在分镜、提示词、生成视频时新写剧情台词。台词只来自编剧岗。
- 5.2 只引用已有资产，不引用还不存在的关键帧文件。
- 先出关键帧并过审，再生成视频。文生视频不进成片主路径。
- 关键帧未过审不得进 6.2；视频未过审不得进剪辑。
- 5.2 生成包未经人确认，不得调用任何生图或生视频接口。
- 失败要诊断并打回对应岗，不要只重摇。同一镜达到 generation_budget.max_attempts 仍失败，简化镜头或改覆盖，不许无限生成。
- 一集指定一个 target_model 主路径，不要镜镜换模型。
- 项目按 Recipe 目录归档，每岗只写自己的文件夹。
- 现有能用的目录、命名、模型调用代码尽量保留，只改职责边界和交接格式。
- 有冲突时：岗位说明书 > 本总令 > 现有代码注释。
- 不要接入名导人格包、三维预演岗、平台绑定（Higgsfield/TapNow 只可参考方法）。

## 11 岗顺序

小说 → 编剧 → 视觉资产 → 分镜设计 → 分镜说明书(5.1) → 生成包(5.2) → 关键帧(6.1) → 视频(6.2) → 声音 → 剪辑

制片统筹负责按此顺序放行或打回。

## 改造时先交付

1. 现有模块与 11 岗对照表
2. 计划改哪些文件
3. 每岗输入输出将改成字段表里的哪些结构

未输出这三份并得到确认前，不要大规模改代码。
